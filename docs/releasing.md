# Releasing

Private DAV MCP releases are immutable container images published to GitHub Container Registry.
The CI workflow also creates a GitHub release for a matching semantic-version tag.

## Prepare a release

1. Update `project.version` in `pyproject.toml` and `__version__` in
   `private_dav_mcp/__init__.py` to the same `MAJOR.MINOR.PATCH` value.
2. Refresh the lockfile with `uv lock`.
3. Run the normal quality and container contract checks.
4. Verify the intended tag locally:

   ```bash
   uv run python scripts/check_release_version.py v0.1.0
   ```

5. Commit the version change, then create and push the matching annotated tag, such as `v0.1.0`.

A tag whose version does not match both package version declarations fails before an image is
published.

## Published image tags

Every push to `main` publishes the full Git commit SHA and the mutable `main` tag. A release tag
also publishes normalized semantic tags such as `0.1.0` and `0.1`. Deployments should pin the full
image digest, not a mutable tag.

## Supply-chain controls

Before publication, CI:

1. Builds the production image and runs the black-box MCP contract suite.
2. Fails on fixed HIGH or CRITICAL operating-system or Python vulnerabilities reported by Trivy.
3. Publishes the image with maximum-mode SLSA provenance and an attached SPDX SBOM generated by
   BuildKit.
4. Signs the published digest with keyless cosign using GitHub Actions' OIDC identity.
5. Creates generated GitHub release notes after the image is published and signed.

The runtime image does not include uv, pip, setuptools, build caches, the project working tree, or
test files. Only the installed production virtual environment and Python runtime are copied from
the builder stage.

## Verify an image

Resolve and retain the image digest, then verify the GitHub Actions signature:

```bash
IMAGE=ghcr.io/bebaek/private-dav-mcp@sha256:REPLACE_ME
cosign verify \
  --certificate-identity-regexp \
  '^https://github.com/bebaek/private-dav-mcp/.github/workflows/ci.yml@refs/(heads/main|tags/v.*)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "$IMAGE"
```

BuildKit publishes the provenance and SBOM as OCI attestations associated with the same digest.
Use `docker buildx imagetools inspect "$IMAGE"` or another OCI-referrer-aware client to inspect
available manifests and attestations.

## Dependency maintenance

Dependabot checks uv, Docker, and GitHub Actions dependencies weekly. GitHub Action references stay
pinned to full commit SHAs even when their version comments are updated.
